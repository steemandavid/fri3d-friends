# Documentation vs. Code audit — 2026-08-11

A full pass comparing the project's documentation (README.md, DESIGN.md, the
implementation-plan docs) against the actual code in `app/`, `server/`, `tools/`
and `tests/`. Each finding lists the doc claim, the code reality with a
`file:line` anchor, and a severity. Resolutions are recorded at the end.

Five parallel reviewers covered: (A) README app files & config, (B) README menu /
controls / UI, (C) DESIGN.md BLE protocol, (D) tests & tooling, (E) Gotcha plan
currency. Findings below are de-duplicated across reviewers.

Severity key: 🔴 high = misleading or actively wrong; 🟠 medium = materially
stale; 🟡 low = minor omission / stale history; ⚪ outside the repo (memory).

---

## 🔴 High

### 1. README: "Y button" to swap contacts does not exist
- **Doc:** README §1 (L12–13), heading `## Swapping contacts (Y button)` (L184),
  L186 — "press **Y**".
- **Code:** no Y handler. Swap is the menu row `("Contact ruilen", "swap")`
  activated with **A** (`fri3d_friends.py:2765`, `_do_menu_action("swap")` →
  `_do_exchange()` `:2819`). A comment states the menu *"replaced the old
  A/B/Y/START button-legend"* (`fri3d_friends.py:154`). The README's own
  Controls table (L262–266, A/X/joystick only) is correct, so the intro + swap
  section contradict it. Pressing Y does nothing today.

### 2. README: "B button" to mute does not exist
- **Doc:** README Configure (L117–118) — sound *"Toggled with **B**"*.
- **Code:** no B handler. Mute is the menu row `("Geluid: …", "mute")` via **A**
  (`fri3d_friends.py:2766`, `_toggle_mute` `:2882`). (The "persisted" half is
  correct: `_save_config("sound", …)` → atomic write.)

### 3. README: the "join a group" ASCII mock is wrong + self-contradictory
- **Doc:** README L198–213 shows groups pre-ticked `[x]` with a legend
  `A: next  B: tick  Y: join`, prose "starts ticked … a single Y".
- **Code:** groups start **unchecked** (`fri3d_friends.py:2661`); **A** toggles a
  tick (`_on_adopt_group_clicked` `:2724`); a separate **"Meedoen"** button joins
  (`:1945`, `_on_adopt_join_clicked` `:2730`); no such legend exists. README's own
  Controls section (L273) correctly says "start unchecked … then Meedoen".

### 4. README "Project layout" omits 4 shipped modules
- **Doc:** the app-dir listing (L327–333) names 11 files.
- **Code:** the dir also ships `gotcha.py`, `gotcha_app.py`, `gotcha_gatt.py`
  (~150 KB, the whole Gotcha game) and `state_backup.py` (the install_mpk
  config-restore the README itself references at L409–412).

### 5. DESIGN §3 specifies the v1 wire format; code radiates v2
- **Doc:** DESIGN §3 (L142–148) — `[HSNT][ver 0x01][gcount]…`, "version byte
  `0x01`".
- **Code:** `ble_proximity.py:26` `VERSION = 2`; `build_payload` (`:332–339`)
  emits an extra `blocks` byte. `parse_payload` still accepts v1, but the live
  beacon is v2.

### 6. DESIGN §4 "✅ verified on-air" row says `ver 1`
- **Doc:** DESIGN §4 (L187) — `… rssi −75 ver 1 gids [0xa07b] …`.
- **Code:** `VERSION = 2`. The verified row is from the v1 era; as written it
  contradicts the shipping beacon.

### 7. DESIGN §12 says `beacon_service` is advertise-only; it is a full victim responder
- **Doc:** DESIGN §12 (L570–577) — "Advertise-only … no scanning, alerts or swaps
  in the background."
- **Code:** `beacon_service.py` builds `BLEProximity + ContactExchange +
  GotchaService + headless GotchaController`, registers GATT, `ble.begin`,
  `gc.start()`, ticks the controller every `POLL_MS_RADIO=250 ms`
  (`:527–530`, `:66`) and fires buzzer/LED effects via `_on_engaged/_on_killed/
  _on_spotted/_on_dodged` (`:343–383`). This is the Phase-4 background victim
  responder; §12 still describes the old v0.7.0 beacon.

## 🟠 Medium

### 8. DESIGN §3 name budget `20 − 2×G` is the v1 number; v2 is `19 − 2×G`
- **Doc:** DESIGN §3 (L152) — "truncated … to `20 − 2×G` bytes".
- **Code:** the v2 `blocks` byte adds 1 byte of overhead → `OVERHEAD` includes it
  (`ble_proximity.py:53`); `name_budget` (`:140`) → `19 − 2G` (or `16 − 2G`
  connectable, `14 − 2G` with a game block).

### 9. DESIGN §3 says "No Flags AD" unconditionally; code emits one when connectable
- **Doc:** DESIGN §3 (L138, L152) — "Non-connectable legacy advertising" /
  "No Flags AD".
- **Code:** `build_payload(connectable=True)` prepends a Flags AD
  (`ble_proximity.py:345–347`); `set_connectable(True)` (`:699`) flips the beacon
  to connectable during a live Gotcha game, and `beacon_service` advertises
  connectable.

### 10. DESIGN §12 cadences are wrong
- **Doc:** "5 s watchdog poll" (L581); "re-asserting every ~30 s" (L584).
- **Code:** `POLL_MS_RADIO = 250` / `POLL_MS_IDLE = 2000` (`beacon_service.py:66`);
  `REFRESH_POLLS = 12 × 250 ms` ≈ **3 s** re-assert (`:68`, `:526–529`).

### 11. README test count: "442 tests" — actual is 444
- **Doc:** README L376 — `# 442 tests, no badge needed`.
- **Code:** `grep -rE '^\s*def test_' tests/ | wc -l` = **444** (0 async, 0
  parametrize). Off by 2.

### 12. Main plan §11 presents Phase 3 (duel/Reveal) as unbuilt future work
- **Doc:** `Implementation_Plan_Gotcha_20260726.md:3008–3013` — future-tense
  "Build Reveal first", exit gate "Ends with a real two-badge chase".
- **Code:** built + verified end-to-end — `gotcha.py` `build_attack_payload` /
  `DuelState` / `validate_attack`; `server/gotcha_server/events.py` attack
  handlers; Phase3b doc "✅✅ VERIFIED 0.11.13". Doc-internal drift between the
  main plan and its own phase sub-docs.

  (`ble_proximity.py:222–224`).
- **Code:** `name_b.decode("utf-8", "replace")` (`:417`) — the `errors` argument
  IS passed, so it never raises; bad bytes become U+FFFD. The stated *rationale*
  for `fold_ascii` is wrong (folding still happens at `:322`, so this is a
  rationale/doc error, not a wire bug).

### 18. Phase-3a ship record disagrees across docs

  Neither matches current `0.11.29`; inconsistent history.
